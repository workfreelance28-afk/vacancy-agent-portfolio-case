# Vacancy Agent — portfolio case

## Что делает

Vacancy Agent помогает находить Junior/Junior+ вакансии для первого коммерческого опыта в AI-интеграции.

Система получает вакансии из внешних источников, применяет жёсткие фильтры, оценивает оставшиеся вакансии локальной LLM через LM Studio, сохраняет результат в SQLite и отправляет подходящие карточки в Telegram.

Отклик остаётся под контролем человека: пользователь сам выбирает вакансию, проверяет её, отправляет резюме и пишет сопроводительное письмо.

## Моя роль

Я спроектировал продуктовый сценарий, архитектуру пайплайна и границы ответственности между Python-кодом, внешними источниками, локальной LLM, SQLite, Telegram и пользователем.

Моя зона ответственности:

- продуктовая логика поиска и отбора вакансий;
- критерии жёсткой фильтрации;
- интеграция источников вакансий;
- подключение локальной модели через LM Studio;
- сохранение результатов и статусов в SQLite;
- Telegram-доставка карточек;
- локальный read-only API;
- тесты, обработка ошибок и ограничения;
- разделение production-пути и экспериментальных функций.

## Архитектура

Основной путь:

```text
SuperJob / Habr / HH
→ нормализация вакансий
→ жёсткие фильтры
→ локальная LLM-оценка через LM Studio
→ SQLite
→ Telegram
→ ручное решение пользователя
```

Ключевой принцип: LLM предлагает оценку, но не принимает критические решения за пользователя и не отправляет отклики автоматически.

## Что доказывает проект

Проект показывает, что я умею собирать прикладной AI workflow вокруг реальной пользовательской задачи:

- подключать внешние источники данных;
- отделять детерминированную бизнес-логику от LLM-этапа;
- проектировать human-in-the-loop сценарий;
- сохранять результаты так, чтобы их можно было проверять позже;
- делать Telegram-интерфейс для принятия решений;
- обрабатывать сетевые ошибки, повторы, недоступность модели и частичные сбои источников;
- не добавлять автоматизацию там, где она создаёт риск ложных утверждений или потери контроля.

## Ограничения

- Это личный рабочий инструмент, а не коммерческий SaaS.
- Источники вакансий могут менять API, HTML и правила доступа.
- HH оставлен как резервный источник из-за ограничений анонимного поиска.
- Habr Career используется через ограниченный HTML-parser публичного каталога, не через официальный API.
- Локальная LLM может ошибаться, поэтому её оценка не является финальным решением.
- Генерация резюме, писем и автоматическая отправка откликов не входят в текущий production-путь.
- Платные API не подключаются без отдельного объяснения цены, назначения и рисков.
